Standard .14 source map

Paths below are relative to this complete GameMaker project. A script named X
lives at scripts/X/X.gml; its YY file registers it with the project.

Game control and presentation
objects/oControl owns platform input, main menu/pause transitions and display
state. Create_0.gml initializes it; Step_0.gml updates it. Draw_64.gml is the
Draw GUI path and Draw_77.gml presents the game scene from Post Draw.
Other_4.gml is Room Start; Other_5.gml is Room End and clears spare effect-cache
images. CleanUp_0.gml releases remaining controller-owned cache resources.
set_widescreen handles camera/display geometry and presentation helpers, including
the native 3:2 choice. draw_gui and draw_gui2 retain the original gameplay HUD.

Touch controls
touch_layout computes on-screen control geometry. touch_keys reads those controls
and preserves the selected hold/toggle behavior. The touch options object drives
the scale and horizontal-spacing sliders; drawing and hit testing must use the
same geometry. Saved setting names and button bindings are stable interfaces.

Localization
port_localization loads and caches port captions on language changes, preserves
original font handles, selects fallback only for missing glyphs and wraps text.
datafiles/lang contains runtime catalogues and glyph-ink metadata. get_text remains
the inherited text lookup. Language selector indices and artwork prefixes remain
stable even when a language has a separate display name.

Rendering and Nano
effect_surface_cache owns reusable scratch/trail surfaces, generations and releases.
water_strip_batch submits cached strip geometry from oWaterFXV2, with the existing
zero-height/shader fallbacks. It selects the appropriate full/Nano water shader.
nano_effects limits cosmetic particles while preserving gameplay RNG consumption.
nano_light_cache operates in oLightEngine scope and owns the room lighting cache.
Nano state is loaded/saved through load_gameoptions and save_gameoptions. These
rendering policies retain their existing gameplay and visual behavior.

Save and Android bridges
scr_save_sync owns shared-save state and synchronization scheduling.
extensions/AM2RSaveTransfer contains file validation, transfer and shared-folder
coordination. The original save codec/validation paths remain authoritative;
changing a file or key name requires checking compatibility and recovery behavior.
extensions/AM2RHaptics contains the independent vibration bridge.

Inherited gameplay
characterStepEvent and chStepSetSprite coordinate Samus behavior and animation.
Enemy/boss objects retain their own events. Room instance/creation data remain in
rooms/. Imported __ scripts implement compatibility with the original project;
preserve their registration and the legacy numeric asset references.

Relationship to Dual Screen
This project builds independently. Common port helpers remain equivalent where
behavior is shared; the other edition adds thor_* modules and an Android display
extension. Do not copy its rendering guards or panel assumptions into Standard
solely to make the file contents match.

Read CODE-STYLE.txt for conventions and README.txt for project/build entry points.

Version .14 touch layout
Touch Aim Balance in Control Options divides the existing left control footprint
between diagonal arrows and the joystick. touch_layout_apply computes drawing and
touch hit areas from the same balance value. Scale and spacing remain independent.
The touch options viewport keeps the final Done entry reachable and visible.
